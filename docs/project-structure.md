# Project Structure

This document describes the current structure of the Cobalt project and explains where its headers, source files, tests, and documentation are located.

## Directory Structure

The current project structure is:

```text
Cobalt/
├── include/
│   └── cobalt/
│       ├── cobalt.h
│       ├── dtypes.h
│       └── tony.h
│
├── src/
│   └── cobalt/
│       ├── cobalt.c
│       └── tony.c
│
├── test/
│   └── test1.c
│
├── docs/
│   ├── project-structure.md
│   ├── tony.md
│   └── img/
│       └── tony.png
│
├── build/
│
├── CMakeLists.txt
├── Makefile
└── README.md
```

> `build/` contains generated build files and libraries and is not part of the source code.

---

## `include/cobalt/`

The `include/cobalt/` directory contains Cobalt's **public header files**.

```text
include/
└── cobalt/
    ├── cobalt.h
    ├── dtypes.h
    └── tony.h
```

These headers define the interfaces that users of Cobalt can include in their programs.

### `cobalt.h`

`cobalt.h` is the **main public header** for Cobalt.

It includes the other public Cobalt headers, so users normally only need:

```c
#include <cobalt/cobalt.h>
```

There is no need to manually include every Cobalt header:

```c
#include <cobalt/cobalt.h>
#include <cobalt/dtypes.h>
#include <cobalt/tony.h>
```

Instead, the recommended approach is simply:

```c
#include <cobalt/cobalt.h>
```

`cobalt.h` acts as the main entry point to the Cobalt API.

---

## `src/cobalt/`

The `src/cobalt/` directory contains Cobalt's **implementation files**.

```text
src/
└── cobalt/
    ├── cobalt.c
    └── tony.c
```

The `.c` files contain the actual implementation of the functionality declared by the public headers.

For example:

```text
include/cobalt/tony.h
        │
        │ declares
        ▼
   Tony API
        │
        │ implemented by
        ▼
src/cobalt/tony.c
```

The implementation files are compiled by the build system into Cobalt's libraries.

---

## `test/`

The `test/` directory contains test programs used to verify Cobalt's functionality.

```text
test/
└── test1.c
```

Tests use Cobalt through its public API rather than depending directly on its internal implementation.

For example:

```c
#include <cobalt/cobalt.h>
```

This helps ensure that the public interface works correctly from a user's perspective.

---

## `docs/`

The `docs/` directory contains documentation for Cobalt and its individual components.

```text
docs/
├── project-structure.md
├── tony.md
└── img/
    └── tony.png
```

Component-specific documentation can describe how individual parts of Cobalt work internally and how they are intended to be used.

---

## `build/`

The `build/` directory contains **generated build artifacts**.

For example:

```text
build/
└── lib/
    ├── libcobalt_static.a
    └── libcobalt_shared.so
```

This directory is generated by the build system and should not be treated as source code.

---

## `CMakeLists.txt`

`CMakeLists.txt` contains the project's **CMake build configuration**.

CMake is Cobalt's actual build system. It is responsible for configuring and building the project and generating the static and shared libraries.

---

## `Makefile`

The `Makefile` provides a convenient interface for common build operations.

Instead of requiring users to invoke CMake commands manually, they can simply run:

```bash
make
```

The Makefile acts as a lightweight convenience layer around the CMake build system.

---

## `README.md`

`README.md` is the main introduction to the Cobalt project.

It provides a high-level overview of Cobalt, its current features, build instructions, documentation, development status, and roadmap.

Detailed implementation documentation is kept inside `docs/`.

---

# Including Cobalt

Cobalt provides a single main header for users:

```c
#include <cobalt/cobalt.h>
```

This is the **recommended way to include Cobalt**.

Because `cobalt.h` already includes Cobalt's public component headers, applications do not need to include each individual Cobalt header separately.

For example, a program using Tony can simply do:

```c
#include <cobalt/cobalt.h>

int main(void)
{
    tPtr memory = talloc(100);

    /* use memory */

    destroy(memory);

    return 0;
}
```

This keeps the public interface simple:

```text
                 <cobalt/cobalt.h>
                         │
              ┌──────────┴──────────┐
              │                     │
       Cobalt public APIs      Cobalt data types
              │                     │
              └──────────┬──────────┘
                         │
                    User program
```

Individual headers such as `tony.h` and `dtypes.h` exist to organize Cobalt's API internally and provide component-level interfaces, but **`cobalt.h` is the normal entry point for users**.

---

## Design Principle

Cobalt separates its project into three main areas:

```text
include/     → Public interfaces
src/         → Implementations
docs/        → Documentation
```

This separation keeps the public API independent from the implementation and makes the project easier to navigate as Cobalt grows.

The intended user experience is simple:

```text
User program
     │
     ▼
<cobalt/cobalt.h>
     │
     ▼
Cobalt API
     │
     ▼
libcobalt.so / libcobalt_static.a
```

**One main header. One library. Simple integration.**
